# Andrômeda — Frontend (SEI Platform)

Plataforma de **Software Engineering Intelligence**: correlaciona consumo de IA (tokens) com métricas ágeis (DORA, velocity, cycle time). TCC de Eng. de Software. Este repo é **só o frontend**; o backend (`andromeda-ms`, Java/Spring Boot) vive em repo separado e **já existe** — várias telas consomem endpoints reais.

## Stack & comandos
- Vite + React 18, `react-router-dom` v6. Sem TypeScript. Estado de servidor em **React Query**; estilo com **Tailwind v4** (a partir da change `frontend-foundation`).
- `npm run dev` (porta 5173) · `npm run build` · `npm run preview` · `npm run format` / `format:check` (Prettier + class sort) · `npm run e2e` (baseline visual Playwright).
- **E2E em Docker (baseline visual determinística)**: `npm run e2e:docker` / `npm run e2e:docker:update` (este passa `--update-snapshots=all`) chamam `scripts/e2e-docker.mjs`, que roda `mcr.microsoft.com/playwright:v1.60.0-noble` com `E2E_MODE=replay` (só fixtures, sem backend) contra o Vite do host via `host.docker.internal:5173`. Funciona de qualquer shell (o cwd é resolvido em Node; argumentos extras vão para o `playwright test`, ex.: `npm run e2e:docker -- e2e/routes.spec.js`). **Pré-requisito:** o Vite precisa estar de pé no host com `npx vite --host 127.0.0.1 --port 5173` (é o bind que o container alcança neste setup); com a 5173 ocupada, suba o Vite em outra porta e passe `E2E_PORT=<porta>` ao script — aí o navegador do container abre `localhost:5173` (como no CI) e `scripts/e2e-forward.mjs` repassa para a porta do host. Só esse modo reproduz o `ai-connector-tutorial.png` (a URL do conector mostra `localhost:9090` só com host localhost); com `host.docker.internal` ele falha desde antes. Baselines só se regeneram no Docker — nunca com o Chromium do host: no host, rode com `--ignore-snapshots` (ou `--update-snapshots=none`), senão o Playwright grava os PNG que faltam.
- Backend em `:9090`; Vite faz proxy de `/api` (`vite.config.js`). Cliente HTTP em `src/core/api/client.js` (`BASE_URL` = `VITE_API_BASE_URL` ou `/api`; JWT em `localStorage` sob `andromeda_token`, anexado como `Authorization: Bearer`; 401 dispara logout). Cada feature tem `features/<x>/api.js` delegando ao client (o antigo barrel `services/api.js` foi removido).

## Arquitetura
- Entrada: `src/main.jsx` (monta `QueryClientProvider`) → `src/App.jsx`.
- **Rotas** (`App.jsx`, `BrowserRouter`): públicas `/`, `/login`, `/signup`, `/onboard`. App autenticado = **layout route** (`app/ShellLayout.jsx`: sidebar + banner + `<Outlet/>`) em `/:orgSlug/*`; cada seção é uma **página independente** sob `features/<nome>/` — `projetos`, `pessoas`, `organizacao` (+ `cargos`/`senioridade`), `dashboard`, `backlog`, `repositorios`, `integracoes`, `uso-ia` (+ `precificacao`), `perfil`. Gate por rota (`RequireTab`), identidade via `useIdentity()`. O `AdminSettings` monolítico foi desmembrado (`frontend-feature-slices`).
- **Dashboard**: a rota `dashboard` e o modo só-dashboard renderizam `features/dashboard/v2/DashboardsPage.jsx` (dashboards por permissão, Resumo personalizável, endpoints `/v1/dashboards/*`). O dashboard antigo (`/v1/dashboard/*`) saiu na troca da change `dashboards-customizaveis` (P5). Detalhes em `features/dashboard/v2/CLAUDE.md`.
- **CSS**: tokens em `src/styles/tokens.css` (fonte da verdade) + `globals.css` (camadas Tailwind, `@theme inline` projeta os tokens; **preflight desabilitado**). `src/styles/legacy.css` é quarentena congelada — só decresce (ratchet; sem sweeps de conversão). Temas via `data-palette` (`default`/`mono`/`light`). **Fontes** servidas pelo app (`@fontsource/dm-serif-display` e `@fontsource/jetbrains-mono`, versão exata, importadas em `src/main.jsx`): nada de Google Fonts pela rede (privacidade e baseline estável entre containers).
- **Primitivos** em `src/core/ui/`: `Modal`/`ConfirmDialog` (Radix Dialog), `Field`, `Combobox`, `Checkbox`, `Slider` (Radix), `Drawer` (próprio, com focus trap — ver `docs/adr-001-drawer.md`), `PageHeader`, `ListCard`, `MetricGrid`. Pele em `core/ui/ui.css`. Não reimplemente backdrop/escape/foco.
- **Tipografia e cabeçalhos** (passada de design geral, 2026-10): o `html` tem 13 px, então a escala do Tailwind é redefinida em px no `@theme` (`text-xs` 11 · `sm` 12 · `base` 13 · `lg` 15 · `xl` 18 · `2xl` 22 · `3xl` 26 · `4xl` 32). **Piso de 11 px** para qualquer texto (rótulos em caixa-alta); texto corrido ≥ 12 px. Toda página abre com `PageHeader` (`h1` 32 px + subtítulo ≤ 72ch) — ou `StickyPageHeader` (Backlog, Repositórios, Uso de IA, Integrações, Organização, Pessoas): a linha do título gruda no topo do `admin-main` (top negativo = padding do contêiner, lido em runtime), encolhe para 22 px com `actions` à direita, e quando o seletor de projeto (`watchRef`) passa por baixo dela o `compact` ("Trocar projeto", nome acessível próprio) aparece no meio com FLIP a partir do original; altura constante para não empurrar o conteúdo; bloco dentro da página usa `SectionHeader` (`h2` 22 px, `description`, `actions`, `id` para `aria-labelledby`). Não use `admin-section-title` para subseção.
- **Seletor de projeto** (Backlog, Repositórios): `useSelectedProject(projects, { ready })` (features/projects/hooks.js) abre já com um projeto — `?projeto=` da URL → último usado (`localStorage` `andromeda_last_project:<orgSlug>`, comum às telas) → o primeiro — e `ProjectSwitcher` (core/ui) troca com um clique (botões em `radiogroup` até 6 projetos; acima, `Combobox` com busca). Nos e2e em replay, telas que só navegam/fotografam Backlog e Repositórios chamam `stubEmptyProjectData(page)` (e2e/api.mjs): o projeto escolhido sozinho busca dados que o replay não tem.
- **Menu lateral** (`app/ShellLayout.jsx`): trilho de 76 px fixo no grid; abre por cima do conteúdo no hover (120 ms de espera; fecha 200 ms depois de sair) ou no foco pelo teclado, só onde há hover (≥ 761 px). Sem botão de fixar.
- **RefreshControl** (`core/ui`): uma pílula só — `↻` + idade do dado ("há 3 dias", com "Atualizado" só para leitor de tela), ponto de aviso com mais de 1 dia, data completa no `title`; ao atualizar o ↻ gira, o texto vira "Atualizando 1/2" e a borda de baixo é a barra de progresso. Os textos longos ("1 de 2 integrações concluídas", "Tente de novo em…") ficam em `role=status` `sr-only`; falhas seguem num `alert` visível. Nome acessível do botão: "Atualizar dados do projeto (…)" / "Atualizando…" / "Aguarde Ns".
- **Modais**: o `Modal` sempre tem o × no canto (`showClose` padrão `true`; ele vem depois do conteúdo no DOM para o foco inicial cair no 1º campo). O `eyebrow` nomeia a área (Cargo, Projeto, Convite, Uso de IA, Integração…) e o título diz a ação — não repita o título no eyebrow. Datas em pt-BR (dd/mm/aaaa), moeda `US$` com `toLocaleString("pt-BR", { currency: "USD" })`.
- **Textos de ajuda** (`info` do `Panel`, descrições): o que o gráfico mostra → como ler → limite, em linguagem simples e ≤ ~200 caracteres; sem jargão solto (p85, p50, "normalizado") sem explicar.
- **Tweaks** (`components/tweaks/TweaksPanel.jsx`): painel de dev para paleta e atalhos de navegação (só em dev). Os botões de entrar como persona fake foram removidos — a identidade vem do login real.
- Wizards multi-etapa usam `components/OrbitWizard.jsx` (animação orbital). Os mocks (`src/data/`) foram removidos; as telas consomem a API real (verifique a tela antes de assumir).
- Pastas: `src/features/<área>` (páginas de rota + `api.js` + `hooks.js`) · `src/core/{api,ui,auth}` · `src/app/ShellLayout.jsx` (layout route) · `src/components` (UI de layout ainda não promovida) · `src/lib` (`orbit.js`, `appUrl.js`, `orgRoutes.js`). Não há mais `src/services/` (barrel removido) nem `src/features/admin/` (monólito extinto).

## Regras de negócio (essenciais)
- **A identidade dirige a interface** — não há rota por cargo. A identidade vem de `GET /v1/auth/me` (`buildIdentity` em `core/auth/shell.js`, exposta por `IdentityContext`/`useIdentity()`), então **refresh preserva a identidade** enquanto o JWT for válido. `isAdmin` é derivado (`USER_MANAGE` **e** `ROLE_MANAGE`), não é um campo do backend. (Os botões de persona fake do Tweaks foram removidos — teste papéis com logins reais de usuários distintos.)
- **Permissões**: o gating usa os **códigos reais do backend** (`USER_MANAGE`, `ROLE_MANAGE`, `AZURE_CONFIGURE`, `AZURE_READ`, `REPOS_CONFIGURE`, `REPOS_READ`, `AI_READ_OWN`, `AI_READ_ALL`, `DASHBOARD_INDIVIDUAL`/`_TEAM`/`_STRATEGIC`, `PRICE_TABLE_MANAGE`, `CONNECTOR_TOKEN_MANAGE_*`, `PROJECT_MANAGE`, `PROJECT_ACCESS_ALL`). Checagem por código = `hasOrg`/`canOnProject`/`holdsAnywhere` do `useIdentity()` — **nunca** `can(...)`, que recebe um id de **aba** (`canSee`) e, para um código de permissão, cai silenciosamente em `isAdmin`. Os antigos `GITHUB_*` viraram `REPOS_*` (`vcs-core-refactor`). Labels e escopos em `core/auth/permissionLabels.js`. **Exceção herdada:** Projetos e Pessoas ainda checam os ids legados `gerProjeto`/`gerEquipe` (`canSee` em `core/auth/shell.js`) — não existem no backend; migrar para códigos reais é dívida conhecida.
- **Escopos (`project-scoped-permissions`)**: cada código é `ORG_ONLY` (gestão, configuração, tokens, dados próprios, `PROJECT_ACCESS_ALL`) ou `PROJECT_SCOPABLE` (`AZURE_READ`, `REPOS_READ`, `DASHBOARD_TEAM`, `DASHBOARD_STRATEGIC`, `AI_READ_ALL`) — fonte: `scope` de `GET /v1/permissions`. O cargo é **preset**; cada usuário tem overrides `GRANT`/`DENY` na org ou por projeto (projeto > org > cargo; DENY vence no mesmo nível). Códigos de projeto valem nos projetos em que a pessoa é **membro**, em todos com `PROJECT_ACCESS_ALL`, ou onde houver `GRANT` no projeto.
- **Identidade com escopo**: o `/v1/auth/me` traz `orgPermissions` e `projectPermissions` (`{ projectId: [códigos] }`); `permissions` = `orgPermissions` (compat). `useIdentity()` expõe `hasOrg(code)`, `canOnProject(projectId, code)`, `holdsAnywhere(code)`, `projectsWith(projects, code)` e `refreshIdentity()` (relê o /me após mudar memberships/overrides — as permissões não vêm mais do JWT). Não há projeto selecionado global: páginas presas a projeto aparecem se o código vale em **algum** projeto, e o seletor de projeto de cada página (Dashboard Equipe/Estratégico, Repositórios, Backlog) filtra pelos projetos com o código; a aba Equipe some quando o projeto selecionado não tem `DASHBOARD_TEAM`.
- Gating por aba (`canSee`): Projetos→`gerProjeto`|admin · Pessoas→`gerEquipe`|`USER_MANAGE`|admin · Dashboard→`DASHBOARD_INDIVIDUAL` ou `DASHBOARD_TEAM`/`_STRATEGIC` em algum projeto · Backlog→`DASHBOARD_TEAM` em algum projeto|admin · Repositórios→`REPOS_READ` em algum projeto|`REPOS_CONFIGURE`|admin · Integrações→`AZURE_CONFIGURE`|`REPOS_CONFIGURE`|`AZURE_READ`/`REPOS_READ` em algum projeto|admin · Uso de IA→`AI_READ_OWN`|`AI_READ_ALL` em algum projeto · Perfil→todos · Cargos/Senioridade/Organização→admin.
- **Permissões individuais**: Pessoas → editar → "Ajustar permissões" (`features/users/permissions/`: preset, overrides por escopo, prévia do efetivo com origem cargo/organização/projeto); painel de membros do projeto ajusta os overrides daquele projeto; Perfil mostra "Minhas permissões" (leitura). Códigos que o chamador não possui no escopo ficam bloqueados (o backend responde `PERMISSION_ESCALATION_DENIED`).
- **Projetos/Pessoas (contrato do backend)**: criar/editar/finalizar/excluir projeto (`POST/PUT/DELETE /v1/projects`) exige `PROJECT_MANAGE` (ORG_ONLY) — sem ele o painel do projeto fica só-leitura; mexer nas pessoas do projeto continua em `USER_MANAGE`. Ninguém troca o próprio cargo (`USER_SELF_ROLE_CHANGE_DENIED`) nem se desativa (`USER_SELF_DEACTIVATION_DENIED`): no modal de Pessoas o seletor de cargo fica desabilitado para si mesmo e os dois códigos (403, `err.body.code`) viram mensagens pt-BR.
- **Gating no front é só UX.** A barreira real DEVE ficar no backend (`@PreAuthorize` com o mesmo código de permissão). Nunca confiar no cliente.
- **Sem permissão de gestão** (nem `gerProjeto` nem `gerEquipe`) ⇒ **sem barra lateral**: só o dashboard (modo só-dashboard), com o botão Sair no cabeçalho.
- **Deep-link/refresh** exige fallback SPA → `index.html` no host (Vite dev já faz; o backend que servir o front precisa de catch-all).
